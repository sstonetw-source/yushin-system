# 主倉分配原介面續傳

相依 #358，關聯 #291。已入庫的後端主倉調撥改提供獨立「核對／續傳分配」，不再次提交收貨。原實貨結果尚未確認時先拒絕分配，要求核對原收貨操作。

送出前保存 UID／角色／專案／transferId，連點共用進行中請求；回覆遺失或 active／retry 保留原來源暫存，刷新後恢復列獨立於查詢結果。後端回覆須核對原來源 movement、數量上限、已分配量及 recoveryPending；只有確定 completed 才清除暫存。切帳、旗標關閉、壞暫存及錯誤回覆不清除、不重建來源、不回退 client writer。

共用 SDK／專案／權限檢查。前後端皆仍僅支援 demo-yushin Emulator；Preview 即使有相應旗標也拒絕，直到共用核心另行完成 Preview 邊界。介面提示保留實貨與分配的獨立狀態。調撥單上的 allocationCompleted 不是權威，因此本批不以它隱藏或宣稱後端分配已完成；已收貨來源可能繼續列入核對清單，下一階段需提供權威分配狀態讀取及清單收斂。

更新 app 與兩個模組的資產版本，產生檔由原始碼重建。Node 測試覆蓋回覆遺失／刷新、原來源重送、連點、未完成保留、停旗標、壞暫存、切帳與錯誤回覆。真 Chrome／Auth／Preview 與集中人工驗收尚未執行；遠端 CI 狀態另記 PR。未合併main、部署、開正式旗標、改Rules或正式資料。
