# 訂單建立：自行訂貨預設與交易方式

- 業務、工程師與管理員在新增訂單選擇自行訂貨時，預設為「已向供應商下訂」。仍可改回尚未下訂；恢復草稿及編輯既有品項不覆寫已保存的選擇。
- 採購代建維持尚未下訂，交由負責業務確認；原有權限不變。
- 新訂單必須選擇直、借或扣。介面、共用建單服務及 Firestore Rules 同時限制。發票抬頭仍於開發票打單時檢查。
- 舊訂單未填交易方式且沒有修改該欄位時，可繼續既有流程；不得清空或移除交易方式。
- Forecast 單品項及多品項都先開既有訂單表單，確認交易方式後建立一張訂單。保留原負責人、來源版本檢查與同筆交易的來源連結，並沿用舊版未完成轉單的編號。
- 交付方式沿用既有的人員預設與客戶地址預設，當次可修改；不新增 Collection、Listener 或預設記憶機制，不追改舊訂單的交付快照。

## 發布需求

前端合併後由 GitHub Pages 發布。此變更需要另外發布 Firestore Rules；不需要 Functions、Index 或 Firebase Hosting 發布。應先確認前端已提供必填欄位，再發布 Rules，避免舊版前端建立空白交易方式訂單被拒絕。
