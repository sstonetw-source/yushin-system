# 訂單與採購工作清單統一

訂單、待採購、待到貨、待打單與採購已完成的清單使用相同資訊順序：單號與日期、客戶、商品、負責業務、目前進度與操作。商品摘要共用已載入資料，顯示品名、廠牌、貨號及具有明確名稱的數量。

- 訂單將進度獨立成欄。價格計算、來源估價單、交付設定及原有編輯欄位在「查看明細」展開；編輯權限、到貨後鎖定與儲存處理沿用既有邏輯。
- 部分打單與部分到貨仍顯示各自數量；確認送達及確認打單的按鈕使用動作名稱，歷程入口統一為「查看紀錄」。
- 工作統計標明品項／供應及銷售／採購金額；不改變原有計算公式、日期範圍或成本可見權限。
- 採購各工作分頁共用「搜尋目前工作」，僅比對已授權且已載入的單號、客戶、負責業務、廠牌、貨號及品名。完整歷史搜尋仍留在採購單分頁，保留原有資料查詢。
- 使用既有暖灰商務 CSS 變數。桌面維持表格，手機使用卡片，日期及業務資訊保持可讀，操作觸控高度至少 44px。
- 所有新增樣式限定螢幕介面，未修改正式單據 PDF、列印範本、後端服務、Firestore Rules、Index 或交易計算。

## 驗證

- 產生的 app.js 與來源一致；JavaScript 語法及差異空白檢查。
- 一般自動化測試 1,877 項。
- 真實 Chrome、隔離測試資料：訂單桌面／手機的服務進度、價格明細、五角色編輯限制及到貨後鎖定；打單原有跨頁重試及不確定回覆流程。
- 真實 Chrome、隔離測試資料：四個採購工作清單在 1440、1024、390px 的共用欄位、文字跳脫、搜尋、五角色打單操作、空狀態及不新增資料讀取。
- 此變更未進行正式環境交易測試；本機瀏覽器資料替身不代表 Firebase Emulator 或正式 Firebase 驗證。
