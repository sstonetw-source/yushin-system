# 訂單金額與明細編輯期限

「訂單總額」改為「訂單金額」。主列表保留正式訂單總額，並顯示每項單價 × 訂單數量＝品項總價；多品項逐項列出，不因列表狀態篩選而把訂單總額誤當作部分品項金額。價格計算僅供顯示，不重寫單據事實或 PDF。

明細集中顯示每項採購方式及交付方式、整張訂單的交易方式與訂單備註。採購方式只讀。一般業務／工程師只修改自己的訂單，管理員保留原有管理權限；採購及倉管不因 UI 增加商業欄位寫入權限。

經確認，訂單明細的交付設定、交易方式及備註在第一批到貨前可修改；任一品項收到貨（包含第 30 項）或已有到貨事件，即鎖定整張訂單。原有已交付、核銷與取消限制同時保留。交付方式若已調撥、交接、進入保管倉或出貨則更早鎖定。到貨後倉庫必要的物流／退回設定仍走既有 scoped 操作及權限，不能藉此改交易方式或備註。原廠直送僅能調整收件資訊，不能改成倉庫配送或調撥。

儲存交易／備註會重讀雲端、確認角色、負責人、到貨狀態與欄位是否被他人變更，再寫入修改紀錄。尚未確認成功前不改畫面數值；重複點擊不重送，回覆中斷後重試會讀取已保存值，避免重複紀錄。明細於更新後保持展開。核銷日期仍使用原有獨立權限及流程。

Rules 同步檢查到貨期限；一般業務不能從普通 items 更新繞過交付計畫專用寫入路徑。無新 Collection、Listener、Index 或背景讀取；僅於使用者儲存時增加必要的一筆訂單交易讀取。

發布需要前端及另行發布 Firestore Rules，不需要 Functions、Index 或 Firebase Hosting。尚未合併 main、未部署正式環境、未做正式環境測試。測試結果以 PR 描述記錄為準。

## 訂單與採購資訊統一
採購需求、待打單、已完成、待到貨與單一採購單商品統一為品名、廠牌與貨號、數量；到貨以已到貨／應到貨／待到貨呈現。確認動作改為「確認已下訂」「確認已打單」，取消未到貨收進可鍵盤開啟的「更多」。直接採購移至標題右側。共用螢幕樣式維持暖灰配色、44px 操作高度與手機換行，不改列印、權限、查詢或庫存計算。已核銷原有撤回操作保留，避免將既有可操作功能錯誤隱藏為唯讀標籤。

新訂單最多 15 品項：手動新增、轉單儲存、共用建單服務與 Rules 建立限制同步；不截斷資料。既有 16–30 品項訂單仍可繼續後續作業與讀回確認，更新規則保持相容。
