# 訂單、採購、庫存與分析修正（2026-10-06）

- 待到貨圖卡、清單摘要與庫存待收貨數字，統計實際尚未到貨的供應品項；包含客戶已取消但供應商採購仍有效、備貨、直送與分批採購。多筆採購來源可在畫面合併為同一訂單品項，摘要會說明。
- 待到貨金額改用未到貨數量 × 供應單的紀錄成本，不再混入整張客戶訂單售價。缺成本會標示待補，倉管不顯示成本。
- 快速採購與正式採購，在待到貨／庫存待收貨清單都有「取消未到貨」入口，只取消點選供應品項的未到貨餘額，保留已收貨、同張採購單其他品項及歷史文件。權限仍限管理員、採購。
- 整張採購單的取消操作仍保留在採購單更多選單。
- 已取消的客戶訂單可對實際已送出而尚未退回的數量登錄退貨。管理員可操作所有訂單，業務、工程師受原訂單歸屬限制；採購、倉管無客戶退貨權限。
- 修改退貨增加數量時，先扣除該筆既有退貨使用的批次，僅還原新增數量；縮減／刪除仍沿用既有批次沖回。
- 正常訂單的退貨重新保留給原訂單補送；取消訂單的退貨放回可用庫存，不重新占用。
- 舊版只有「已送貨」旗標而沒有送貨明細的單品項／多品項訂單，分析納入銷貨，以訂單日期推估送貨日並標示。若已有送貨紀錄，以實際紀錄為準，不重複加總。
- 成功交易後，進銷存分析下次開啟會重新讀取資料，避免沿用取消／退貨前的報表。

本次沒有修改正式業務資料，也沒有修改 Firestore 規則。前次新增的後端權限規則仍需要有權限的 Firebase 帳號部署，見 permission-fixes-20261006.md。沒有各角色登入狀態，尚未做正式網站各角色的手機／桌機完整操作實測。
