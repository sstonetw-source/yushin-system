# 預留位置差額與現行憑證核對

基準 main：`6e3dac3`（PR #81）。這一批把預留快照的差額計算收斂至 reservation-core，接入現行憑證流程；**仍未啟用多倉預留或多位置分批履約**。

## 計算與接線

`reservationStockDeltas(before, after)` 接收兩份完整預留快照，回傳 `companyReservedDelta` 與 `warehouseDeltas[].reservedDelta`。公司量相同的換倉仍回傳來源負數、目的正數，不能因總量沒變就忽略位置變動。相同快照沒有差額；純計算不更動輸入，也不代表提交、角色授權或調撥完成。

新版位置提案重用 `reservationLocations`／`validateMultiLocationLedger`，只接受版本 2、正整數、唯一位置及精確總量。未標版本、未知版本、混入另一套位置欄位、錯產品與異常數量都停止。舊單維持既有小數量、數字字串與業務保管位置語意，不將舊單自動升版。

| 現行接線 | 行為 |
|---|---|
| 採購／倉管預留證據 | 用共用差額判斷是否需要證據，取代兩段分開比較總量與倉庫的邏輯；原庫存／movement／來源證據格式與限制不改 |
| 業務／工程師庫存憑證 | 對交易內寫入的公司與分倉 stock，先合計同產品／對應位置的來源預留差額。數量不一致時不產生原生寫入；不更動庫存來配合錯誤提案 |
| 文件識別碼 | witness 的 reservationIds 使用 reference.id，歷史文件內錯誤 id 不可導向其他預留 |
| 執行時依賴 | stock-permissions 在交易時取得共用核心，適用現行腳本順序；新核心缺失時停止，不能跳過核對 |

業務核對沿用既有小數比較容差 `1e-9`，不將實際 stock 四捨五入。它是較早的錯誤回饋，**不是安全邊界**；缺漏 stock 寫入、直接 API、歸屬、角色與數量仍必須通過既有 Rules。管理員未新增這項業務憑證檢查，也未擴大任何角色權限。

## 尚未接線的邊界

PR #81 的 JavaScript 與 Rules 未啟用位置欄位保護完整保留。因此共用函式雖可計算 v2 提案，live 交易仍不能讀寫該格式。沒有產生第二套 ledger 或新的資料庫格式。

調撥途中仍由 stockTransfers 與既有專用證據描述；來源實貨可能已扣除、目的尚未入庫，不能將預留 warehouseId 的變動直接當成同時兩倉現貨移轉。本批不改動調撥出發／收貨證據，也不擅自把預留搬到目的倉。後續需把途中責任、實際到貨、各位置交付與 Rules 同批整合，才可解除多倉限制。
