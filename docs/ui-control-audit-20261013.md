# 全系統按鍵／工作分頁樣式盤點（2026-10-13）

## 目的與範圍

本次以 `main` 的工作介面為基礎，盤點八個主要模組的操作按鍵及工作分頁。只整理螢幕 UI 樣式，不更動交易、權限、Firestore、列印文件版面。重點是以既有 B 方案暖灰商務變數集中管理，減少逐頁覆蓋。

## 現況盤點與統一方式

| 模組 | 已確認的控制形式 | 共用規則 |
| --- | --- | --- |
| 估價單 | `sub-tab`：建立／全部估價單、YS／MS／DS 公司切換（div role=button） | 工作分頁 |
| Forecast | 新增、搜尋、狀態篩選、列表操作（button） | 主要／次要按鈕、觸控高度 |
| 產品管理 | 搜尋／清除／加入估價單、動態廠牌按鍵（product-brand-button） | 主要／次要按鈕、工作分頁 |
| 訂單 | 新增訂單、狀態卡（order-work-card）、處理進度頁籤 | 主要按鈕、工作分頁 |
| 採購 | 採購需求／採購單／供應商、階段卡、工作按鈕 | 工作分頁、階段選取、主要／次要按鈕 |
| 倉庫 | 庫存／收貨／出貨、收貨種類、出貨目的地及工作按鈕 | 工作分頁、階段選取、主要／次要按鈕 |
| 儀器管理 | 新增儀器、上傳／匯出、列表操作 | 主要／次要按鈕 |
| 管理員後台（含進銷存分析） | 後台工作 `sub-tab`、分析 `sub-tabs`、價目表操作 | 工作分頁、主要／次要按鈕 |

頂層功能選單 `nav-tab` 屬「主導覽」，保留獨立的版面排法，但配色仍使用同一組 `--ys-*` 變數。危險操作 `btn-danger` 保留紅色語意；資料狀態標籤不等同可點擊的操作按鈕，不應被當作選取頁籤處理。

## 原始問題

1. 估價單、採購、倉庫、分析後台使用不同 HTML 標籤和 CSS，導致相同的切換功能視覺不一致。
2. 部分早期樣式寫死深藍、亮藍、灰底，較新的暖灰樣式只能再加覆蓋規則。
3. 有重複的 `btn-secondary`、`btn-danger`、`order-work-card`、`product-brand-button` 選取樣式，以及同一個估價單按鍵的專屬宣告。
4. 只檢查 CSS 是否存在，不能驗證電腦／手機實際繪製的高度或色彩。

## 此次處理

- 新增統一 `--ys-control-height`（44px）及 `--ys-control-radius`（8px），保留既有主要、次要、選取及危險色票。
- 將 `sub-tab`、`purchase-view-tabs`、`order-progress-tabs`、分析 `sub-tabs`、`order-work-card`、`product-brand-button` 集中為同一組螢幕樣式。
- 選取狀態相容 `.active`、`aria-selected="true"`、`aria-pressed="true"`，不必變更任何切換 JavaScript 或商業狀態定義。
- 刪除舊版控制項的重複主色宣告，保留各模組必要的 `flex/grid` 佈局及手機欄數。
- 更新 `styles.css` 版本以避免手機讀取舊快取。
- 新增靜態回歸與桌機／手機尺寸 Chrome 樣式測試，避免新增頁籤時只改某一模組。

| 項目 | 電腦版（1280px） | 手機版（Playwright 模擬 390px） |
| --- | --- | --- |

| 選取／未選取色彩、圓角 | 自動檢查 | 自動檢查 |
| 主要按鍵深藍／次要暖白 | 自動化回歸與 CSS 檢查 | 自動化回歸與 CSS 檢查 |
| 44px 最小觸控高度 | headless Chrome | headless Chrome |
| 工作分頁是否超出視窗 | N/A | headless Chrome |
| 現場真實資料、權限切換、登入後各個對話框 | 尚未執行 | 尚未執行 |
| 正式估價單／採購單 PDF 目視校稿 | 非此次變動範圍 | 非此次變動範圍 |

**注意：** Playwright 以 Chrome 模擬 390px CSS 視窗，但這仍非 iPhone Safari 實機驗證。headless Chrome 使用代表性的 HTML 與正式 CSS，不等於已登入 Firebase 正式環境逐頁人工驗收，不能宣稱正式環境已驗證。日後重要改版應另外做角色別瀏覽器實際操作。

## 未來共同維護規則

- 新的工作分頁重用現有控制型式與共用 CSS，**不得再新增每個頁面獨立的選取色**。
- 要修改全站按鍵尺寸／圓角／狀態，先改 `--ys-control-*` 與同一段工作分頁樣式，不透過在檔案底部持續新增覆蓋。
- 互動分頁要保留鍵盤與可辨識文字；需要危險操作時使用 `btn-danger`，非主要動作使用 `btn-secondary`。
- PR 預設跑 `ui-design-guidelines`、`ui-controls-regression` 與 Chrome 樣式 smoke；正式部署前仍要人工抽查手機與桌面。
- 歷史 CSS 中與此次控制項**無關**的採購流程、訂單狀態、版型與 PDF 樣式維持原狀，沒有證據證明不再使用前不得批量刪除。
