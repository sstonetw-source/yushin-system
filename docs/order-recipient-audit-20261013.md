# 寄給負責業務：收件資訊檢查

基準：最新 main 4816a97（2026-10-13）。

既有功能已提供收件人、電話、地址輸入，以及訂單 shippingInstructions 快照；倉庫使用品項 deliveryPlan（若曾單獨調整），否則使用訂單 shippingInstructions。出貨清單、CSV、地址貼紙、出貨／交付紀錄沿用此快照，不會因個人預設變更而更新。寄送缺少三項任一資料時，既有儲存與出貨驗證會阻擋。

本次補缺：

- 採購改選負責業務時，重新帶入該業務收件資訊，清除前一位的訂單地址；保留直接寄客戶的地址。
- 尚未選定業務時，不回退到建單人的個人資料。
- 保存已選業務，避免背景名單初始化還原選項；後續背景初始化不覆蓋選擇結果及人工修改。
- 明確標示「寄給我（寄給負責業務）」、「聯絡電話」、「完整收件地址」。
- 訂單明細逐品項顯示實際收件快照，缺資料顯示未填寫提示。

不改動庫存／採購／送貨數量、角色判斷、正式單據 PDF 或 Firestore Rules。沒有新增 Collection、Query、Listener、Index 或 Firebase 設定。

權限靜態檢查：建立訂單仍由既有角色驗證與負責業務選項驗證控制；地址預設寫入仍限管理員；訂單交付修改沿用 canSetPlan 與 Firestore 的商業歸屬／交付設定限制。新增明細只顯示已載入訂單的資料。

- 全部純 Node 自動化測試 907 項通過（包含業務、採購、倉庫、工程師、管理員既有角色回歸）。
- 新增回歸涵蓋採購切換業務、缺省資料不回退、獨立訂單地址、不回寫個人預設、快照匯出、三項必填驗證。
