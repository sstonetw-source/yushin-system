# 又鑫公司系統正式架構（2026-09-23）

本文件先固定資料與商業流程邊界；效能優化在架構驗收完成後另行處理。

## 1. 核心分層

每個訂單品項必須把三件事分開記錄，不以單一狀態欄混用：

1. `fulfillmentType`：貨怎麼到客戶。
   - `WAREHOUSE`：經公司倉庫／公司人員交貨。
   - `DIRECT_SHIP`：供應商或原廠直送客戶，不進公司庫存。
2. `supplyMode`：貨從哪裡取得。
   - `STOCK`：使用現有庫存。
   - `STANDARD_PURCHASE`：一般採購。
   - `PEER_TRANSFER`：同業／關係企業調貨。
   - `ADVANCE_DELIVERY`：先行交貨；正式含義確認前不得啟用資料異動。
3. 數量履約：`orderedQty`、`reservedQty`、`supplyOrderedQty`、`receivedQty`、`dispatchPreparedQty`、`deliveredQty`、`returnedQty`、`shortageQty`。

狀態由數量推導；不得以「已訂貨／已到貨／已送貨」布林值作為新流程的唯一真相。歷史布林欄位只保留相容讀取。

## 2. 已確定的供貨流程

### 現有庫存

- 訂單成立：Available 足夠部分立即 Reserved；On Hand 不變。
- 採購在既有出貨系統完成打單後記錄 `dispatchPreparedQty`。
- 業務／工程師實際送貨：On Hand 與 Reserved 同量下降，建立 Delivery、Movement 與批次配置。

### 一般採購

- 建立正式 PO 只增加 Incoming／供貨紀錄，不增加 On Hand。
- 倉管實際收貨才建立 Receipt、Lot、Lot Cost 與 Movement，Incoming 下降、On Hand 上升。
- 部分到貨立即優先補最早缺貨訂單的 Reservation。

### 業務／工程師自行訂貨

- 建立 `SALES_SELF_ORDER`，必須有供應商、數量、實際成本與內部訂購單號。
- 只允許負責業務／工程師查看自己的自行訂貨成本；正式採購成本仍由採購／管理員控管。
- 倉管依訂購單號收貨，收貨後走與一般採購相同的 Lot／庫存流程。

### 同業調貨

- 正式資料使用 `supplyMode = PEER_TRANSFER`，不得把它當作廠牌或一般庫存調整。
- 產品通常屬 `NON_AUTHORIZED`；實際調貨成本記在交易／供貨層，不覆蓋代理產品標準成本。
- 必填：供應公司、終端客戶、不可取消註記（若供應條件要求）、數量、成本、預計日期。
- 經倉庫時建立 Incoming 並由倉管收貨；直接送客戶時搭配 `DIRECT_SHIP`，不建立公司庫存。
- 是否可取消由該筆供貨條件決定，不能全系統一律假設可取消。

### 先行交貨（決策 Gate）

目前不得實作或啟用，必須先確認它代表下列哪一種：

- 客戶端先行：客戶正式訂單／文件未完成，但公司先把貨交給客戶。
- 供應端先行：供應商先交貨，公司採購文件之後補齊。

兩者的庫存、信用風險、核准人、後補文件及報帳條件不同，不可共用同一狀態。

## 3. 五角色資料異動邊界

| 資料／動作 | 管理員 | 業務 | 工程師 | 採購 | 倉管 |
|---|---|---|---|---|---|
| Forecast／估價／訂單 | 全部 | 自己 | 自己 | 可代建，必須指定負責業務 | 不可改商務欄位 |
| 自行訂貨 | 全部 | 自己 | 自己 | 可檢視／協助 | 只收貨 |
| 正式 PO／同業調貨供貨單 | 全部 | 不可 | 不可 | 建立與維護 | 收貨欄位 |
| 打單完成 | 全部 | 不可 | 不可 | 可記錄 | 不可 |
| 實際送貨／退貨 | 全部 | 自己 | 自己 | 查看 | 庫存作業範圍 |
| 倉庫、Brand Master | 全部 | 不可 | 不可 | Brand 不可；供應商可 | 不可 |
| 收貨、Lot、效期 | 全部 | 不可 | 不可 | 可 | 可 |
| 受保護成本 | 全部 | 僅負責產品線或自己的非代理交易 | 同業務 | 全部採購成本 | 可寫收貨成本、不可讀回 |
| 儀器 | 全部 | 自己 | 全部工程管理 | 依頁面授權查看 | 無商務異動 |

前端的管理員「切換視角」只驗證畫面；真正寫入權限仍由登入帳號與 Firestore Rules 決定。

## 4. Desktop／iPhone 驗收矩陣

每個角色均須在 Desktop Chrome 與 iPhone 主畫面 Web App 執行：登入、清單讀取、新增、修改、重複點擊、背景切換後返回、權限拒絕及重新整理。正式異動驗收使用獨立測試資料前綴 `UAT-YYYYMMDD-角色-裝置`，驗收後以作廢／停用保留稽核，不直接刪除。

必測交易鏈：

1. Forecast → 多品項估價 → 訂單。
2. 全現貨、部分現貨、全缺貨。
3. 正式採購與自行訂貨。
4. 部分到貨、補 Reservation、部分打單、部分送貨。
5. 取消、恢復、部分退貨、報帳切換。
6. 原廠直送與倉庫混合品項。
7. 同業調貨（資料模型完成後）。
8. 先行交貨（商業定義確認後）。

自動測試負責資料不變量、重複操作與 Rules；實機驗收負責版面、輸入、iOS 背景生命週期及實際按鍵流程。兩者都通過才算完成。

## 5. Brand Master 相容層移除 Gate

正式主檔是 `brands`。相容層目前仍合併舊價格來源、統計設定與分公司代理設定。

移除前必須全部成立：

1. `products`、價格來源、統計品牌／別名、分公司代理品牌、供應商對應中的每個品牌，都能由 Brand Master 正式名稱或 alias 對應。
2. 歷史訂單、估價、Forecast、儀器中的未對應名稱已逐一確認是別名、停用品或可保留的交易快照。
3. 管理員後台「Brand Master 相容層稽核」顯示正式來源缺漏為 0。
4. Desktop／iPhone 的品牌選擇、公司代理限制、統計歸類、供應商自動帶入均通過。
5. 完成資料備份與獨立 commit 後，才可刪除 `getUnifiedBrandEntries()` 中的舊來源合併；不得同時刪除歷史交易內的品牌快照。

目前狀態：只新增只讀稽核工具，尚未移除相容層。
