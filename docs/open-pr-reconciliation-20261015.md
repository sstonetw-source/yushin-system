## 操作與數量影響

- 所有原可看產品的角色可直接輸入完整貨號；選廠牌仍會限制結果。仍是 normalizedPartNo 精確等值查詢、50 筆分頁及原快取，不搜尋全部產品、不加入 Listener／Index。停用產品與成本權限不變。
- 建單同步未完成時，訂單保留且有重試入口，顯示同步中／未完成，不先宣告待採購。取消／作廢仍顯示關閉狀態。沒有批量回填歷史訂單工作索引。
- 公司顯示的可用量若高於本次交易所讀的啟用實體倉合計，停止該品項預留、品項更新與需求投影；可能原因包括資料差異及停用倉尚有貨。畫面要求核對，不偷偷調整庫存。既有正數預留與已有供應／履約承諾不重新選倉。
- 管理員在銷售分析可按「隱藏毛利／顯示毛利」，同時控制毛利、毛利率卡片、明細與目前分頁 Excel；不重查資料。採購金額、庫存估值與原本角色權限維持既有定義。這是展示選項，不是新增資料授權。匯出等待載入 Excel 工具時若改成隱藏或離開管理員角色，取消該次匯出。
- 手動新增庫存與批次文字更新不改變實際入庫、收貨、採購、取消或退貨的數量。估價單單號與正式 PDF 排版未改。

## 測試邊界

新增針對同步工作分類、取消優先、公司／分倉不符停止、隱私卡片／明細／匯出與等待期間變更的行為測試，並保留全部原應用回歸。原隔離交易替身改為每次 attempt 使用同一份讀取快照，避免把公司舊數量與同時提交後的分倉新數量混在同次讀取中；原版本衝突重試測試保留。

新增實際 `reserveSingleOrderItem` 的 Emulator 測試，驗證業務、工程師、採購、管理員遇公司有貨／分倉無貨時，不部分提交或建立採購需求。既有角色拒絕與正式 Rules 回歸繼續執行。倉管不能接管建單同步，權限不放寬。

新增桌面 1280px／手機 390px Chrome fixture，使用實際產品／分析 HTML、事件函式與共用 CSS，檢查未選廠牌也能輸入與啟用搜尋、隱藏毛利後卡片及明細一致、按鈕 44px 與手機不溢出。資料為隔離 fixture，不是正式登入走單。

最終測試結果以整合 PR 的 head CI 為準。未修改 Firestore Rules／Index，不需因本批更新 Firebase 設定；沒有正式部署、正式資料修復／刪除或新的完整多倉履約驗收。原有尚未部署的 Rules 需求仍以各批文件為準。
