# 取消與恢復訂單的預留守恆

基準 main：`1a1702f`（PR #82）。本批修正現行單倉生命週期入口，不啟用多位置寫入。

## 發現與修正

舊取消邏輯使用 `min(本品項預留, 分倉預留)`，不足時仍把 reservation 與訂單品項清成零。公司預留也以零為下限截斷，可能掩蓋原本的數量差異。業務憑證／Rules 常會拒絕這種交易，但管理員入口不可依賴角色限制代替正確計算。

共用 `planReservationLifecycle` 先核對訂單投影與實際預留，確認公司／分倉有足量預留；一致才完整釋放。負數、非有限值、null、預留超過實貨或來源不一致都停止，不以縮量或覆寫當作修復。舊單小數量與數字字串維持可計算；不更動 onHand 或批次成本。

恢復重用 `planReservation`：既有預留先保留，只對真正增減寫 movement 與庫存，零可用量不送出無變動 stock 寫入，不將原預留重加一次。新增量同時受公司與該分倉可用量限制，公司自由調撥途中量不算現貨。尚未到貨的供應商承諾沿用原計算，避免同一缺口同時預留現貨與待採購。

多品項共用交易內 stockStates，前一品項使用後的公司上限供下一品項重算。後項異常使整筆失敗，不提交前項已排入的釋放與訂單更新。來源訂單／itemId／產品／倉庫與預留或庫存位置衝突時停止。原本只在品項投影保存的非零預留不再自動重建，需先核對權威資料。

有 transferPendingId 時停止取消與恢復，待目的倉點收，不將途中責任當成現貨。業務保管位置仍可依原流程取消，不進入一般自由庫存分配。直送或未連結產品品項若帶有實貨預留，不能直接清零。

## 驗證

- 新增 15 項 Node 行為驗收，包含精確釋放、公司／分倉上限、途中與供應承諾、既有預留、小數／異常數量、三角色實際取消、管理員異常資料拒絕、來源衝突、保管位置、多品項守恆、後項失敗及直送相容。
- 本機語法、diff 及完整 1,091 項應用測試通過。
- 新增兩項實際函式 Emulator 驗收，涵蓋管理員／業務／工程師取消異常資料不改帳、合法取消後恢復成功，以及恢復受公司可用量限制。完整 142 項 Emulator 與桌機／手機以最終 CI 為準；不是正式環境驗收。

## 發布與未結案

沒有新增 Query、文件讀取、Collection、Listener、Index 或 Rules。重用既有交易快照，保留重試與身分檢查。更新 reservation-core、app 與頁面說明，資源版本 `20261015-4`；stock-permissions 沿用上一批版本。

這是前端交易品質與異常資料防護，直接 API 仍依既有 Rules，未宣稱新增後端權限保護。未部署正式 Firebase、修復或刪除歷史資料。多倉啟用限制保留；多位置履約、調撥責任與 Rules 整合尚未完成。

恢復仍沿用原倉，未新增倉庫主檔讀取、停用倉重新選倉或跨倉分配，這些接線仍需後續處理。採購需求的生命週期同步仍是既有提交後步驟，失敗保留原提醒；本批沒有改成同筆原子交易或宣稱該缺口已結案。

## 第 85 批接續：恢復訂單的倉庫主檔檢查

恢復訂單時，原本只確認庫存與預留數字，卻沒有在同一交易確認原倉庫是否仍存在、啟用及為實體倉庫。已停用、已刪除或改成業務保管位置的倉庫，即使保留舊庫存資料，也不能直接恢復預留；**同一訂單全部品項停止，未提交任何庫存、訂單或預留變更**。新建及取消流程維持原邏輯；取消既有預留仍可釋放停用倉庫的保留量。

交易內重讀倉庫主檔，每個不同倉庫最多新增一筆文件讀取，同張訂單多品項共用 snapshot，並保留先讀後寫。直送品項不讀實體倉主檔。未新增 Query、Listener、Collection、Index、角色或權限；前端不自動修改舊訂單的倉庫欄位，也不嘗試將保管位置當作普通現貨。當倉庫已停用，使用者收到明確錯誤，需由管理員先查核原倉、調撥及預留紀錄，不能為了恢復而直接移動帳面庫存。

驗證涵蓋管理員／業務／工程師，缺少主檔、停用、systemCustody、CUSTODY 類型與 custody- 前綴，以及後一品項失敗不得部分提交；實際 Firestore Emulator 以 PR CI 結果為準。這是現有前端作業完整性檢查，**不是直接 API 的新 Rules 防護**。後續仍需設計有條件的跨倉重新配置與生命週期採購需求同筆原子更新，不能以本批防呆視為已完成。正式 Firebase 尚未部署或驗收。

## 第 86 批：取消訂單時同步關閉既有採購需求

取消訂單的既有 procurementDemands 文件，現在隨同訂單狀態、實貨預留、公司／分倉 reserved 與庫存事件，在**同一個 Firestore transaction** 更新為 CANCELLED、待採購量 0。交易先讀取全部品項的既有需求，再排入寫入；任一筆需求與訂單的來源、品項、產品或歸屬不一致，整筆停止，不能留下「訂單取消但採購需求未取消」或已釋放部分庫存。已下單量及已收到量不會清零，既有供應商合約仍需採購依原流程處理。不存在的需求不另建取消紀錄。

Firestore Rules 新增限定業務／工程師本人的生命週期需求關閉憑證：必須同交易看到同一來源訂單從正常轉取消；僅能更動需求狀態、待採購量、更新時間與同品項索引。不能用此權限改成本、來源、供應已訂量、收貨數量或自行取消別人的需求。管理員／採購沿用原權限。永久刪除未產生取消的採購需求變更，仍需依既有受限刪除流程稽核。

此批**只關閉既有需求的取消階段**；恢復訂單仍沿原本「庫存提交後同步採購需求」的可重試步驟，尚非原子化。歷史取消但需求仍待採購的資料並未批次修復。需先更新 firestore.rules 再發佈前端 app.js?v=20261015-6，避免舊規則拒絕業務同步關閉需求；沒有新增 Index／Collection／Listener。正式環境未部署、未完成五角色真實資料驗收。

## 第 87 批：恢復訂單時同步回復採購需求

恢復訂單的每一筆來源採購需求現在改在同一 Firestore Transaction 中與訂單狀態、庫存預留、公司及分倉數量同時更新。交易讀取來源訂單、庫存、預留、各倉主檔及既有需求後，使用正式訂單品項的新預留量計算採購需求；只要來源身分、已訂購數量、已收到數量或供貨方式不符，全部不提交。已有需求只更新數量投影、需求狀態及品項索引，不覆寫供應商已訂／已收貨事實；原本沒有需求且恢復後仍有缺口的才建立，零缺口不新增空需求。取消訂單仍同步關閉既有需求；永久刪除路徑維持原本跳過需求寫入的例外，尚需獨立稽核永久刪除的關聯完整性。

Firestore Rules 新增限定業務及工程師本人，必須有來源訂單同交易由取消轉為正常且需求原狀態為 CANCELLED，才能修改既有需求的狀態與投影欄位；不允許直接修改已訂購或已收貨數量。原有採購／管理員權限與取消流程不變。系統不再在恢復操作提交後做第二輪非原子需求同步。並未新增 Collection、Query、Listener 或 Index，但恢復每一品項多讀一次既有採購需求。前端版本更新 app.js?v=20261015-7。

本批的 GitHub CI／Firestore Emulator 結果以 PR 版本為準，未在正式環境部署或驗收。正式上線應先部署新版 Rules，再發布前端；不能把 GitHub 合併視為 Rules 已部署。

## 第 88 批：管理員永久刪除未履約訂單的交易完整性

此前「永久刪除訂單」先做獨立庫存釋放，後用 Batch 刪除訂單與預留，因此 Batch 失敗時會留下已釋放預留但未刪除的訂單；採購需求也可能成為沒有來源訂單的孤兒紀錄。

新流程只對**沒有商業來源連結、沒有採購／到貨／送貨／退貨／核銷、且庫存與來源同步已完成的獨立訂單**開放管理員永久刪除。在真正操作前再次讀取供應商紀錄（按 orderId 限 1 筆），只要仍有來源供應紀錄就拒絕。正式刪除交易內重新讀取訂單、每個正式品項的預留與採購需求；核對來源識別、產品、負責人、供應量；若有任何資料異常或採購／收貨事實就整筆拒絕。未取消的訂單透過原本共同 planReservationLifecycle 釋放正確預留；已取消訂單若仍有預留則停止。確認成功才在**同一 Firestore transaction**內移除訂單、對應預留及尚未有供應事實的需求。任一變更失敗整筆回滾，不會留下半刪除狀態。

為避免破壞估價單／Forecast 的成交與文件關聯，任何帶來源文件或正式文件連結的訂單都不能走此永久刪除入口。這是管理員極少使用的例外清理功能，不是一般取消訂單流程，亦不應當作正式商業歷史的清除工具。刪除後 inventoryMovements 及 stockOperations 的既有稽核紀錄仍保留。僅新增刪除時一次供應來源查詢，沒有常駐 Listener、Collection、Index、角色權限或 Firestore Rules 變更，正式環境尚未部署。

限制：供應商來源的預先查詢並非交易內鎖定，若有外部寫入者繞過現有資料一致性規則，仍需額外做關聯稽核；本批不宣稱涵蓋所有歷史異常或跨系統操作。測試包含 Node 原子回滾／來源驗證及 Firebase Emulator 管理員／業務實際權限，最終結果以 PR CI 為準。

## 後續：永久刪除時保留異常採購數量

採購需求的已訂購與已收貨數量必須均為數字零，才能隨未履約訂單永久刪除。負數、非有限數值、文字零或缺漏欄位均拒絕，提示管理員先核對採購需求；拒絕時整筆交易不寫入，訂單、預留、採購需求與庫存均保留。正常零數量的刪除方式不變。

此修補沒有新增查詢、Index、Listener 或變更角色與 Rules；前端版本為 app.js?v=20261015-9。新增回歸測試逐一驗證兩個數量欄位的異常值會停止所有寫入。尚未進行本批瀏覽器、Emulator 或正式環境驗收，亦未正式部署。
