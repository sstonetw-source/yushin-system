# 專案指示符合性修正（2026-10-13）

基準：GitHub main `c1ee22faec29f62f388c9d4a1cbee9f0ff53a3fd`。

## 實際變更

- 庫存批次 create/update 都驗證數量為非負數，禁止直接更換商品、倉庫及來源身分，成本仍放在受限的成本集合。
- 採購／倉管的預留數量或倉庫變更，須提供同一交易的新庫存異動紀錄，並驗證總庫存與分倉預留數量相符。共用 transaction wrapper 自動產生證據，不增加人工步驟或 Collection。
- 同一產品一次最多驗證五筆預留。一般同倉操作只計算一次數量差額，再同步驗證公司與分倉資料，以避免 Rules 計算上限。零數量的直送品項不計入實體預留。
- 跨倉直接交付同步扣來源、加目的；分兩階段的調撥點收，必須關聯原本 IN_TRANSIT、此次 RECEIVED 的轉倉紀錄，驗證來源倉不再重複扣預留。
- 管理員仍保留例外處理權；批次數量及身分檢查也適用於管理員，不增加採購、倉管或業務的其他權限。
- 儀器新增使用同一次編輯的固定文件 ID，送出期間鎖定按鈕；失敗重試沿用同一 ID。既有儀器的維修／保養紀錄改用 Transaction 取得最新陣列後增刪，避免其他人的紀錄被覆蓋。
- 刪除紀錄依紀錄身分比對，不因另一人插入紀錄造成陣列位置改變而刪錯。儀器停用與紀錄更新等資料庫確認後才更新清單。
- 儀器與退貨失敗訊息附上資料識別及處理方式；其他常見失敗訊息補上確認結果、連線／權限與安全重試說明。
- 儀器 Excel 上傳及送貨紀錄編輯改為次要操作；停用儀器不再標為永久刪除。
- 採購交期標籤及時間軸使用共用暖灰 CSS 變數。次要文字加深至 `#626A76`，保持 B 方案主色與底色，並驗證在主要背景上的對比至少 4.5:1。
- 介面、錯誤訊息、核心模組及定義文件統一稱「預留／已預留」，保留原本 reserved 欄位與商業數量定義。
- 本人只能將 users Email 同步為 Auth token 的 Email，不能改姓名、業務代號、角色、啟用狀態、他人資料或寄送偏好。

## 使用方式與商業邏輯

業務、工程師、採購及倉管沿用既有工作流程。儀器儲存會立即顯示處理中，等待資料庫確認後顯示完成；失敗可重試同一次編輯。維修紀錄保留其他使用者已提交的內容。

訂單、部分採購、部分收貨、取消後保留採購到貨、出貨、退貨及調撥的既有定義不變。收貨仍增加現有庫存、釋放在途；已取消訂單不重新預留。新增的交易證據由系統自動寫入，讓後端拒絕不一致操作。

正式估價單及採購單的 PDF／列印區域不更動；灰字對比整理僅套用螢幕工作介面，排除正式單據區域。
