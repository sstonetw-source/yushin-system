# 業務交接前端與原操作恢復

相依 #371，沿用既有訂單調撥傳輸與恢復清單。原批次寄給業務及單筆交付入口以 HANDOFF 呼叫 handoffOrderTransfer，目的地從伺服器訂單 ownerUid 決定；不以交付設定的倉庫欄位作為保管倉。

送出前保存原帳號、角色、動作、來源、目的地、數量及交付設定。相同編號同內容共用進行中請求，同品項未確認的調撥／交接互相阻擋新編號。回覆遺失或讀回失敗保留 sessionStorage；重新整理後於原調撥工作清單確認交接，同一原編號重送並核對伺服器 HANDOFF／RECEIVED 憑證才清除。保管倉必須屬於原負責業務，並核對建立及接收帳號、角色。sessionStorage 僅支援同分頁重新整理，不宣稱關閉分頁或跨裝置恢復。

獨立 YUSHIN_ORDER_TRANSFER_HANDOFF_EMULATOR 旗標，僅 demo Emulator 可用；旗標關閉、帳號角色變更或暫存損壞都不回退舊交易。沿用 #371 的 legacy 單倉限制，尚不支援 v2 custody 或分散多倉。交接不等於客戶交貨。

驗證：本機 Node 2100／2100 通過、來源生成一致性、語法及 diff 檢查通過。新增原站桌面 1280／手機 390 批次交接後丟棄成功回覆、重新整理以原恢復按鈕核對及旗標關閉測試；本機缺少 Emulator／Chrome，真環境結果須以本 PR CI 為準。#371 的 CI 已通過（Auth Callable 74、原站 browser 26），不能代替本批新增測試。
