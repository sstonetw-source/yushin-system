# 訂單介面與自行訂貨流程

訂單建立介面改為「客戶與商品、訂貨方式、交付方式」三區。產品細節、交易與發票、日期與備註預設收合；直／借／扣供採購打單確認發票，直交易另需發票抬頭，並在打單交易內重新檢查最新資料，不阻擋業務核銷；採購代建的負責業務欄位在主要區域顯示。沿用全系統 CSS 變數，手機已加入品項以卡片顯示，觸控欄位與按鈕至少 44px。

## 使用方式

- 業務與工程師：選客戶、貨號，確認數量與含稅售價，再選交付方式。日期預設今天，資料歸屬本人。
- 採購：代建時指定啟用中的業務或工程師；自行訂貨確認仍由負責業務執行。
- 訂貨方式：預設交由採購處理；自行訂貨才顯示進度、供應商與含稅單位成本。
- 自行訂貨：預設尚未下訂，可先留白供應商與成本；確認已向供應商下訂時必填供應商與成本（可填 0）。成立後的未下訂品項，在訂單清單直接提供「確認自行訂貨」，沿用既有視窗與供應商訂貨紀錄。
- 交付方式：我送客戶、倉庫寄客戶、原廠直接送客戶。我送保留主倉自領或寄給負責業務，沿用個人預設。寄件與原廠直送都需完整收件人、電話、地址。
- 多品項：加入下一品項時保存該筆訂貨與交付設定；編輯時恢復。地址、售價或訂貨方式不同的相同產品不合併。新增下一品項清除前一產品成本、供應商與已下訂確認。

## 資料與權限

客戶必填。售價空白在表單草稿中保留為 null，成立前必須確認，明確填 0 才是免費品。產品仍須完成主檔對應。每筆品項保存 deliveryPlan 與收件資訊所屬的客戶；更換客戶後需重新確認舊品項收件資訊。

selfOrderConfirmed 只是建立時是否要登記已下訂的意圖。只有 true 的自行訂貨品項才執行既有供應商登記；尚未下訂不產生 supplyOrders。已下訂數量、待到貨與收貨仍以既有 supplyOrderedQty 與供應商紀錄為準，不新增商業狀態。庫存涵蓋的數量不重複下訂。

複製訂單只複製產品與商業設定，不複製庫存預留、已下訂數量、收送貨紀錄或調撥事實，且重新設為尚未下訂。確定實際下訂的單位成本回填該品項，供應商正式紀錄仍保留成本。

本次沒有新增 Collection、Listener、Firestore Query 或 Index，沒有改角色權限、Rules 或正式 PDF 格式。現有 Rules 驗證成本與供應商下訂權限。本次不實作跨倉自動配置，不把畫面上的「依庫存配置」當作已完成跨倉配置。
