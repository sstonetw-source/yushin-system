# 四項工作介面整理

## 實際變更

1. 訂單每個品項獨立一列／手機卡片，含稅單價 × 訂購數量、品項小計與該品項進度放在一起。同張訂單使用相同單號，最後一列另標整張合計。明細仍直接列出完整訂單。採購既有品項列沿用相同標題、金額字級與暖灰分隔線。
2. 訂單、估價單、採購單及庫存的更多選單共用原生對話框，固定顯示操作對象；整張訂單操作標示範圍。背景鎖定、Esc／背景關閉、回到原捲動位置；移動的是原按鈕而非複製商業資料，保留原處理器與原頁唯讀保護。刪除／取消確認加上客戶與單號。
3. 庫存列表精簡為商品、倉庫與現有／預留／可用／在途。倉庫篩選只使用已載入快取；未確認的倉庫資料顯示待確認，不能冒充零庫存。批號、效期、庫存策略與各倉數量保留在明細；維護操作收進更多，新增／匯入及次要歷史列表預設收合。庫存移出與補貨判斷仍使用公司合計，避免選到空倉誤開放操作。調撥出貨搬到出貨工作區，保留主倉／分倉寄貨、收貨分類與既有交易。沒有待辦時隱藏空表頭與批次操作，資料讀取失敗不顯示已確認的零筆數。盤點介面要求填寫調整原因。
4. 登出旁改為個人設定：唯讀帳號身分、自行維護聯絡電話、主倉自領／寄給業務的預設收件人、電話與地址，以及既有修改密碼入口。儲存前核對、成功後才更新本人快取；修改不重寫既有訂單、客戶地址或物流紀錄。使用偏好留待後續，不新增不必要的設定。

## 資料與權限

- 一般使用者新增的寫入只限 `users/{本人UID}` 的 `phone`、`deliveryDefaults`、`updatedAt`。電話及地址有型別／長度、欄位、模式驗證；時間為 serverTimestamp。活躍帳號只能修改本人，不能修改角色、啟用狀態、代號、Email、改密碼要求或 capabilities。
- 沿用既有人員名單讀取政策、管理員協助設定及固定角色權限。沒有建立 Collection、Index、Listener；個人設定開啟時讀本人一筆文件。
- 未改庫存、採購、出貨、送貨、退貨的交易服務或計算；正式 PDF 不變。
- 不部署 Firebase。個人設定自助儲存需要同步本 PR 的完整 firestore.rules；舊規則會拒絕並顯示請管理員同步的訊息。其他介面修改不依賴這個權限新增。

- 17 組實際 Chrome 測試覆蓋桌面與手機。新測試包含選單背景鎖定／還原／背景與 Esc 關閉、原操作保留、來源頁權限關聯、本人設定儲存及失敗、舊訂單不變、庫存實際列表渲染與倉庫篩選、未知資料不假裝為零、五角色操作及批號明細。
- 語法、產物一致與 diff 空白檢查。
- 全站 Auth／Callable 生命週期整合由 PR CI 再驗證；本機測試不代表正式環境交易實測。未操作正式交易、未發布網站或 Rules。
