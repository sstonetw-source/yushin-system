# 寄貨與調回主倉流程

## 角色操作

| 角色 | 正常流程操作 |
|---|---|
| 業務 | 下訂單、已送貨、核銷 |
| 採購 | 已採購、已打單；有需要時發起主倉備貨調回 |
| 倉管 | 已收貨、已出貨 |

訂單交付方式為主倉自領、寄給我、直接寄客戶。出貨頁只列主倉寄貨與分倉寄貨，可依業務／客戶篩選，列印與匯出收在次要選單。

主倉自領不進倉管出貨清單、不另按已領貨。業務按已送貨前保留訂單占用，帳面現有庫存尚未扣除。寄給業務時，倉管已出貨會移入業務保管並保留占用，不要求業務確認收貨；業務送達後按已送貨。直接寄客戶時，倉管已出貨同時記為已送貨；此狀態代表系統作業完成，不代表物流簽收證明。核銷仍由業務處理。

配送條件、箱件數與物流單號只填快遞公司的寄件單，不在系統重複填寫。系統保留收件資訊與選填特殊備註；出貨清單、地址貼紙與 CSV 不顯示預設溫層或箱件數。

## 調回主倉的兩個來源

1. 訂單明確選主倉自領且配置分倉庫存：自動列出訂單調回需求，沿用原訂單占用，不再重複保留。品項到齊且打單後，分倉寄出按已出貨；主倉實際點收按已收貨，保持訂單占用供業務自領。
2. 採購／管理員在庫存清單發起主倉備貨：建立需求時保留分倉可用數量，現有數量不變。分倉實際寄出按已出貨，移為調撥途中；主倉點收按已收貨後成為主倉可用庫存。未寄出需求可由採購／管理員取消並釋放保留。

需求集中於庫存清單的調撥回主倉區，收貨頁保留調撥收貨。分倉直接寄給業務或客戶不自動調回主倉；缺少交付方式的既有資料不推測為主倉自領。舊的在途調撥仍可點收。

## 發布與驗證

本次新增 `stockTransferRequests` 與 `transferReserved` 保留證據。發布前應將本次完整 `firestore.rules` 部署到既有專案；僅更新網頁無法建立備貨調回需求。權限拒絕時介面會提示更新規則，交易不會部分扣帳。

規則要求採購角色建立／取消備貨需求、倉庫作業角色寄出，建立與狀態變更皆核對原子保留／釋放／調撥證據；數量、倉庫、品項與來源識別不得任意改寫。讀取清單限制 50 筆並標示，匯出的是目前調回清單。

已以交易測試驗證重試不重複扣帳、取消不侵占訂單占用、寄出與點收分開入帳，以及分倉自領不可提前送貨。Firestore Emulator 驗證未授權角色、單獨變更狀態、超量保留、竄改身分、重複取消與重複寄出。正式規則發布需使用具部署權限的 Firebase 登入。
