# 進銷存分析：篩選、明細與讀取範圍

基準：main de235cbb3df1b07ff16e9d10ef45b44f12ac2889。

- 產品類型套用於三分頁的總額、品項明細及 Excel；分類沿用 Product Master，查不到時沿用交易快照。
- 日期、業務、廠牌、產品線、類型集中在同一區，修改條件後按查詢才套用。未套用的條件有提示且停用匯出，避免畫面數字與 Excel 不一致。
- 總額卡片縮小；計算方式可展開；明細預設收合，展開後每頁 50 筆。分頁僅顯示既有資料，不再查詢；匯出包含全部符合條件資料。
- 採購：讀所選成立日期的 supplyOrders、指定客戶來源訂單及相關產品；不讀 receipts、全庫存或所有未完成訂單。
- 銷售：只讀所選成立日期的 orders，指定送貨／退貨批次成本；無批次時讀指定來源訂單的供應資料，以既有唯一對應直送規則確認毛利。
- 庫存：讀正現有數量的 warehouseStocks、正餘量 inventoryLots、指定成本及產品；不讀整批客戶訂單或期間收貨。
- 成立日期／目前履約進度、取消與退貨、含稅銷售及批次成本計算口徑保留。未知成本不當成零；庫存批次數量不一致仍明示未完成估值。
- 以帳號、分頁、期間保存最多每分頁一份快照，有效期 60 秒；切換篩選與分頁可重用。重新進入分析頁強制重讀，成功交易清除快照。載入途中切分頁／角色／交易失效時，不發布舊結果。
- 唯讀變更，不改 Firestore 資料結構、索引、Rules 或交易寫入。現有管理員入口與後端成本讀取權限保留。新 orderId in 查詢使用單欄位條件，其餘使用既有日期及正餘量查詢。
